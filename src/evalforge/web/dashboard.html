How to use EvalForge

  1. Choose a saved test. The baseline is the reference version. The candidate is the changed version you are checking.
  2. Read the result. Passed means required checks were met. Blocked means a quality rule failed. Incomplete means an execution or evidence problem prevented a reliable decision.
  3. Review the questions. Compare both answers and expand their checks or source documents to understand what happened.
  4. Fix and test again. Change your application, documents or configuration, run another evaluation, then select Refresh results.
Create your first result

From the project folder, with EvalForge installed, run the support demonstration:

python -m evalforge.demos.workflow

This uses rules, not AI. It intentionally creates a passing run and a blocked run to demonstrate how EvalForge catches mistakes.

Test actual model-generated RAG answers

Configure the model IDs in examples/rag/live.json and set the provider credential locally. The model and judge must support the configured endpoint. Then run:

evalforge run --config examples/rag/live.json

This example compares a complete document collection with one missing the refund policy. Calls may be paid. Refresh results after the run finishes.

This page reads saved results. Refresh reloads them; it does not run a test or call a model.
